# BugBusters Frontend

## Overview

The BugBusters Frontend is a banking-grade, single-page dashboard built with Next.js and React. It serves as the unified user interface for the entire security scanning platform, aggregating data from multiple backend microservices (Dependency, Configuration, Secret, and Pre-Cipher scanners) into a cohesive risk assessment view. It is designed to present complex vulnerability data, risk chains, and remediation playbooks in an actionable and highly secure manner.

## Key Capabilities (Banking Context)

From a banking and financial security perspective, the Frontend provides critical visibility and strict access workflows:

- **Unified Security Dashboard**: Provides a single pane of glass for all security scans. It visualizes severity-based findings, blast radius mappings, and banking intelligence scores generated by the Risk Engine.
- **Secure Source Ingestion**: Supports both GitHub OAuth integration for authorized repository imports and manual ZIP file uploads for strict offline/archive scanning of air-gapped codebases.
- **Real-Time Log Streaming**: Utilizes Server-Sent Events (SSE) to stream secure, real-time scan logs and progress directly to the browser without requiring third-party WebSocket brokers.
- **Rich Vulnerability Visualization**: Translates raw JSON scanner outputs into human-readable attack paths, risk chains, and compliance mappings, enabling rapid decision-making for security analysts.
- **Enterprise-Grade UI Architecture**: Built on a modern Next.js stack with strict TypeScript definitions and Tailwind CSS, ensuring a scalable, maintainable, and highly responsive user experience.

## Getting Started

### 1. Clone the Repository

Clone the repository to your local machine:

```bash
git clone <repository_url>
cd frontend
```

*(Note: Replace `<repository_url>` with the actual Git URL of the repository.)*

### 2. Environment Configuration

Create a `.env` (or `.env.local`) file in the root of the `frontend` directory to configure the application's connection to the main orchestration backend:

```env
# API Configuration
NEXT_PUBLIC_API_BASE_URL=http://localhost:5000
```

*Note: Ensure `NEXT_PUBLIC_API_BASE_URL` points to the correct host and port of your running Main Backend instance. No sensitive secrets (like API keys or JWTs) should be placed in this frontend environment file.*

### 3. Start the Application

The frontend is a Node.js application managed via Node Package Manager (npm). 

**Manual Setup (Cross-Platform):**

Make sure you have Node.js installed.

```bash
# Install dependencies
npm install

# Start the development server
npm run dev
```

For a production deployment, build the optimized static and server-rendered files first:

```bash
npm run build
npm start
```

### 4. Service Port and Access

By default, the Next.js development server runs on port **3000**.

Once the service has started successfully, open your browser and navigate to:
- **Dashboard Interface**: `http://127.0.0.1:3000`

From here, you can log in via GitHub OAuth (if configured in the backend) or proceed with uploading a local repository archive for offline scanning.
